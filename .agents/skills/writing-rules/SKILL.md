# Writing rules

These rules adapt ASD-STE100 principles for AeroCalculator.

| # | Rule |
|---|---|
| W1 | Write formal, technical English. |
| W2 | Give one subject or instruction per sentence. |
| W3 | Prefer active voice when the actor is known. |
| W4 | Use short, direct sentences. |
| W5 | Use one term for one physical quantity everywhere. Do not rotate synonyms. |
| W6 | State symbols and units explicitly when they matter. |
| W7 | Distinguish a definition, an equation, an assumption, and a limitation. |
| W8 | Use the imperative form for procedures. |
| W9 | Put a condition before the instruction that depends on it. |
| W10 | Use numbered steps for procedures with three or more actions. |
| W11 | Avoid ambiguous pronouns. Repeat the noun when needed. |
| W12 | Avoid marketing words, superlatives, and vague claims. |
| W13 | State measurable behavior instead of intent. Write “the function returns” rather than “the function wants.” |
| W14 | Keep notation consistent with `docs/units_and_conventions.md`. |
| W15 | Give the physical meaning before implementation detail in user documentation. |
| W16 | State the valid range and important assumptions for a numerical model. |
| W17 | Separate user documentation from developer architecture. |
| W18 | Keep a descriptive paragraph focused on one topic. |
| W19 | Use American spelling in new prose. |
| W20 | Do not hide a required instruction inside a note or parenthesis. |

## Review checklist

1. Confirm the technical meaning.
2. Check terminology against the conventions document.
3. Split sentences that contain unrelated ideas.
4. Remove unnecessary adjectives and marketing language.
5. Check every symbol and unit.
6. Check assumptions and validity limits.
7. Check procedures for explicit order and conditions.
8. Read the final text once for ambiguity.
